# mcp — rebar's rules in the AI's memory

Goal #5 of the repository: **keep the MCP alive — the rule changed, the MCP regenerates itself, and the gate fails if it is old.** The design is in [docs/PLANO.md §7.2](../docs/PLANO.md).

The defect it exists so as not to repeat, in the owner's words: *"No Herz e no BMB Compras eu elaborei um MCP com todas as regras de projeto, pra ele sempre ficar na memória e forçar a ser usadas"* [In Herz and in BMB Compras I built an MCP with all the project rules, so it would always stay in memory and force them to be used] — and *"o MCP não era reescrito quando as regras de projeto foram modificadas"* [the MCP was not rewritten when the project rules were modified].

## The three pieces

| Piece | Role |
| --- | --- |
| `tooling/rebar-check/index.mjs` | **The source.** <!--n rules.total-->23<!--/n--> rules, each with its measured why |
| `mcp/generate.mjs` | **The generator.** Derives the artifact from the source |
| `mcp/rules.generated.json` | **The artifact.** <!--n mcp.artefato.tamanho-->139 KB<!--/n-->. Not edited by hand |
| `mcp/src/` | **The server.** Reads the artifact. Never reads `index.mjs` |

What closes the loop is the gate's `mcp` step:

```
npm run verify   →   step `mcp`   →   node mcp/generate.mjs --verificar
```

It regenerates the artifact **in memory** and compares it with the disk. Diverged, it fails. It is impossible to change the rule and forget the MCP.

The server also gives a weaker signal on its own: it compares the `sha256` the artifact recorded in `fontes[]` with the file's hash today and sticks a **FRESHNESS WARNING** onto every answer when the source changed. It is a warning, not a verdict — the gate is the one that decides.

## How the owner turns this on

Claude Code reads **`.mcp.json` at the project root**. Create the file with:

<!-- prova-cliente.mjs reads the block below and STARTS the server with it. If the path
     here is wrong, `npm run prova` fails. The snippet is tested, not promised. -->

```json
{
  "mcpServers": {
    "rebar": {
      "command": "node",
      "args": ["mcp/src/index.mjs"]
    }
  }
}
```

`node`, never `npx`: `npx` on Windows is not an executable, and whoever calls it without `shell: true` gets ENOENT — the defect that survived in the foundation because CI only ran Linux.

**To use rebar from inside ANOTHER project** (a site generated by `rebar new`, for example), point at the rebar checkout by absolute path:

```json
{
  "mcpServers": {
    "rebar": {
      "command": "node",
      "args": ["C:/Users/voce/Documents/rebar/mcp/src/index.mjs"]
    }
  }
}
```

A forward slash works on Windows and saves having to escape `\\` in the JSON.

Before the first use, once, from the root: `npm ci --prefix mcp`. The `mcp/` package has its own dependencies (the MCP SDK and zod) and is **separate from the root on purpose** — the root stays at zero dependencies, which is what makes `npx github:Navesz/rebar` run without installing anything, and the freshness gate (`generate.mjs`) is zero-dependency too, because it runs inside `verificar` and cannot require `mcp/node_modules`.

After editing `.mcp.json`, restart Claude Code and check with `/mcp`.

## The five tools

| Tool | The question it answers | When to call it |
| --- | --- | --- |
| `rebar_regras` | "what is going to fail me here?" | before writing code |
| `rebar_porque` | "why is this a rule?" — with the measured number and the proofs | when the gate fails you and you feel like working around it |
| `rebar_decidir` | "has the project already decided about X?" | before proposing a stack, library, format or process |
| `rebar_portao` | the gate's <!--n mcp.artefato.passos-->25<!--/n--> steps, the command for each one, the exit codes | when the gate fails and the message is not enough |
| `rebar_verificar` | runs the ruler over a path and returns the scoreboard | after touching things, before saying you are done |

### The subject has to reach the rule that fails it

`rebar_decidir` is the tool that can lie in the direction of permission, and on
2026-09-07 it did: asked about `csrf` it answered that nothing in the artifact
decides it and *nobody will fail you over it*, while `disabled-defense` fails the
commit for exactly that. Two causes, both in the extraction: the rule writes its
reason in a JSDoc block and the generator read only `//` comments, so the whole
header was lost and the only paragraph left was the section ruler drawn above it;
and the table of literals the rule greps for never entered the artifact at all.
In the same measurement `rate limit` — which nothing in rebar checks — came back
with the `readme` rule, because the word "limit" appears in a paragraph about
README size.

The artifact now carries a `termos` field per rule, derived from the pattern
tables the rule module exports: the literal word runs of each pattern and the
explanation beside it. And an entry only counts as an answer when the subject is
in something that IDENTIFIES it — its id, its title, the literal it greps for —
or when it covers the whole subject. Half of a two-word subject, found in a
justification paragraph, is a mention, and the empty answer names it as one.

Steps `3b`–`3d` of `prova-cliente.mjs` hold all of it, and the approving side is
not optional: `rls` and `upload` are real subjects rebar does not govern, and
they have to go on being answered with "nobody will fail you over it". Without
them, a change that made every subject match every rule would pass as a fix.

**There is no `rebar_gerar`**, which §7.2 foresaw. rebar's generator (`new/index.mjs`) creates a whole project, runs `shadcn create` and makes the first commit — it is not a component emitter, and a tool that commits contradicts the house rule that the one who commits is the owner. A tool that promises what the repository does not do is the promise nobody checks, exactly what the artifact's `naoDerivado` field exists to record.

## What it is NOT

**The MCP is never the door.** The door is N0–N5: `npm run verify`, the hook and CI. Calling a tool here is a shortcut to not get it wrong; no answer of its own authorizes anything, and a green from `rebar_verificar` does not replace the gate — which still runs `format`, `links`, `secret`, `proofs` and this module's freshness.

It also **does not serve prose**. The previous version of this server returned chunks of `docs/PLANO.md` by section; it was replaced because copied prose is the format Herz proved ignorable (17 guides, 1,961 lines, 80 KB, and the repository itself admitting that *"ferramenta MCP é discricionária, o modelo decide se chama"* [an MCP tool is discretionary, the model decides whether to call it]), and because the plan says what the project INTENDS while the artifact says what the gate FAILS today. When the two diverge, the one that fails commands. The prose is still reachable: the tools return `arquivo:linha` instead of copying the text.

## Proving it runs

```
node mcp/src/prova-cliente.mjs          # handshake, tools/list, every tool, the subject→rule contracts, and the server with no artifact
node mcp/src/prova-cliente.mjs --curto  # only each step's verdict
```

The client is **zero dependency** — only `node:child_process` and JSON — on purpose: proving the server with the same SDK it uses would let an SDK defect cancel itself out on both sides. It speaks JSON-RPC 2.0 in NDJSON over stdio, which is MCP's transport (one message per line; `Content-Length` framing is LSP, not MCP).

Its last step assembles a copy of the server in a folder with no artifact and checks that the process **dies with exit 1** saying how to generate it — instead of coming up and answering "no rule found", which would teach the model that the project has no rules.
